# GBPixelVfx: notes from the plan review (Astra, GPT-6-Astra medium) and the architect's decision on each

Full answer: `Devlog/raw/CENTRAL/2026-11-13/agents/062728-codex-7ba49d/output.txt`. Astra checked the engine source read-only; it could not open `.uasset` files, so everything about how the Niagara Fluids materials behave is still **unverified until the first bake**.
Where a note contradicts `Prompts/pixelvfx_implement.md`, this file wins.

1. **Camera: long-lens perspective, not orthographic** (the fluid ray-march material uses the camera position; ortho is unverified). Decision: the capture uses a perspective `USceneCaptureComponent2D` with a narrow FOV (job key `Capture.FovDeg`, default 10) placed at `Distance = (WidthCm / 2) / tan(FovDeg / 2)` from `CenterCm`; `Capture.DistanceCm` in the jobs is ignored in this mode. `Capture.Projection` = "Perspective" (default) or "Ortho" (kept as an option to try).
   - Scene captures do NOT advance GPU simulations (`FSceneView::AllowGPUParticleUpdate()` excludes them): only the main view does. So the main offscreen game view must render every frame and must look at the effect: place the player's view (a camera actor set as view target) at the same position and direction as the capture camera, with the Niagara component visible to it.
   - The capture may see the simulation state of the previous frame. That is fine: capture at a consistent point of the frame (end of the game mode's Tick) and count frames, never wall time.
   - Show-only lists do work with Niagara mesh renderers (`SceneCaptureRendering.cpp::GetShowOnlyAndHiddenComponents`). If the fluid still comes out empty with the show-only list, the fallback is `PRM_LegacySceneCapture` (render everything; the bake world is empty anyway).
2. **Fixed time step from the command line**: the script now passes `-UseFixedTimeStep -FPS=60` for bakes (the delta of the first frame is chosen before BeginPlay). Keep the `FApp` calls too when a job asks for a `SimFps` other than 60. Before activating the system: `Component->SetRandomSeedOffset(0)` (a fixed value), `Component->SetAllowScalability(false)`, so the bake is not culled or scaled down. Do not promise bit-identical results between runs: the auto-frame pre-pass and the real pass are two simulations, so the auto-frame padding matters.
3. **UncookedOnly + Default loading phase is right.** The cook's Editor process can load the baker module too: the game mode and the module startup must do nothing unless a `-Pvfx...` switch is present. The runtime module must not reference any baker class.
4. **Plugin isolation works** (`-EnablePlugin=` for UBT, `-EnablePlugins=` at runtime), Editor target only. In the `.uplugin`, restrict the Niagara dependency to Editor targets: `"Plugins": [{ "Name": "Niagara", "Enabled": true, "TargetAllowList": ["Editor"] }]`. Never list NiagaraFluids there.
5. **Alpha**: keep the single pass with A = inverse opacity; `AlphaMode` stays per job ("Opacity", "Luminance", "Max"). Additive blending also reduces A in UE's translucency pass, so "Opacity" may already work for fire; look at the first bake and choose.
6. **Lighting wording and options.** The light track is a *stylized lighting approximation*, not the volume's real light transport. Direct shadows come from Virtual Shadow Maps (or ray-traced shadows when hardware RT is on); Lumen does GI and reflections. Decisions:
   - Hardware RT is NOT enabled in the project. The script's `-HardwareRT` switch runs one process with `-dx12 -ini:Engine:[/Script/Engine.RendererSettings]:r.RayTracing=1,r.Lumen.HardwareRayTracing=1`.
   - The Unlit emissive quad is visible to Lumen cards and to ray-tracing hit shaders as it is. Keep `CastShadow = false` on the quad.
   - New: a second sprite material `M_PixelVfxSpriteLit` (Masked, **Default Lit**, two-sided, base color = sample * Tint, roughness 1, specular 0, emissive = sample * Tint * Glow, same params) for effects that do not emit light: smoke. Clip / job key `World.Lit` (bool, default false; clip JSON key `Lit`). A lit pixel sprite receives the scene's light and shadows, including the light of a pixel fire next to it.
   - `Light.TrackMode`: "Baked" (default: the measured envelope) or "Constant" (always 1).
7. **Conversion**: the order in the brief already downsamples linear radiance before any tone mapping; keep it so. Captured RGB over black is already premultiplied: never multiply it by alpha again. Hysteresis only applies when the pixel was solid in the previous frame (already the rule); additionally skip it for a frame whose solid pixel count differs from the previous frame's by more than 30% (fast-changing frames: explosions). Island removal and hole filling default OFF in code (`MinIslandPixels` 0, `FillHoles` false); the jobs decide. Loop cross-blend only when `Loop` is true. Framing and pivot are fixed for the whole clip.
8. **Compare mode**: wall-clock time only (never `FApp::GetDeltaTime` under a fixed step), frame caps and VSync off, warm up each population before measuring, no readbacks or screenshots inside a measured window, and the baked population includes its lights (that is the honest cost). Report it as a quick benchmark, not as proof.
   - PNG decode: `IImageWrapper::GetRawImage` (5.9 recommends it over the format/depth overloads). Check the result and the dimensions (atlas must equal Columns * FrameWidth by rows * FrameHeight); set filter / sRGB / addressing before the final `UpdateResource`; keep the texture and the dynamic material in `UPROPERTY` references so GC does not take them.
   - One-shot clips: when finished, destroy the mesh and light components explicitly (or the owner actor).
   - `ReadLinearColorPixels` needs a real RHI (never `-NullRHI` for bakes).
