# Glyphbound: code architecture

> Written by the architect (Claude Code) on 2026-11-12. Source of truth for how the C++ is organized.
> Design lives in `Design/GDD.md`; this file says how the code implements it. Keep it short and current.

## Principles
1. **Data, not code.** Every gameplay number lives in `Glyphbound/Content/Data/*.json` and is read through `UGBDataSubsystem`. Code never hardcodes damage, costs, speeds, durations, sizes or timings. The JSON ships as loose files, so numbers can be tuned in a packaged build with a text editor (`gb.ReloadData` reloads while playing).
2. **One stat system.** A number is a *named stat*: base value from data, then modifiers. `UGBStatsComponent` evaluates `(Base + adds) * multipliers` (or an override). Skill-tree nodes, armor, status effects, air passives and the weapon enchant are all just groups of modifiers with a source name. Nothing else changes numbers.
3. **One damage path.** Everything that hurts goes through `UGBCombatLibrary::DealDamage(Target, FGBDamageInfo)`. Shields, resistances, teams, on-hit effects and kill credit hook in there once.
4. **Spells are data + a behavior.** A spell is a `FGBSpellDefinition` (params with `Base/Min/Max/ScaledBy`) plus the class of an `AGBSpellActor` behavior. The QTE result (power, reach) scales the params tagged for it. A new spell that fits an existing behavior is a JSON entry, no code.
5. **Shared pieces.** One projectile (`AGBProjectile`) for staff bolts, spell projectiles, enemy shots and grenades. One status-effect component for slows, burns, potions and buffs. One interact interface for portals, chests, pickups and the seal.
6. **Text in git.** No binary assets are required to run: input actions, the test arena, placeholder shapes and placeholder pixel sprites are all built in C++ from text. `Content/` is ignored by git except `Content/Data/`.
7. **No GAS.** Unreal's Gameplay Ability System was considered and rejected for the jam: it needs a lot of boilerplate and asset setup, and the game's needs (costs, cooldowns, timed effects, stat upgrades) are covered by principles 2-4 in a few hundred lines we fully control.
8. **PIE is human-only.** Agents build, run the pure-logic tests and package; a person plays.

## Data files (`Glyphbound/Content/Data`)
`Player.json`, `QTE.json`, `Game.json`, `Spells.json`, `Weapons.json`, `StatusEffects.json`, `Items.json` (items + recipes), `Enemies.json`, `Encounters.json`, `Skills.json`, `Sprites.json`. Schemas are the structs in `Data/GBDataTypes.h` (field name = JSON key). Stat and parameter names are the constants in `Core/GBStatNames.h`.

Modifier keys: an actor stat (`MoveSpeed`), `Weapon.<Id>.<Stat>`, `Weapon.<Slot>.<Stat>` (`Weapon.Staff`, `Weapon.Gun`, `Weapon.Sword`), `Weapon.All.<Stat>`, `Spell.<Id>.<Param>`, `Spell.All.<Param>`, `QTE.TimeDilation`...

Standard status effect ids (defined in `StatusEffects.json`, referenced from other files): `Slow`, `Ignite`, `HealthPotion`, `ManaPotion`, `HealthInjection`, `Enchant_Fire`, `Enchant_Lightning`, `Enchant_Ice`. (`Burn`, `Shock`, `Chill` were removed in GDD v0.22.)

Modifier ops: `Add`, `Multiply`, `Override`, and `MultiplyMin` (only the lowest one on a stat counts: slows never stack, the strongest wins).

Elemental keys (GDD 6 "Elemental build-up"): per enemy in `Enemies.json` `Stats` (`<E>DamageTaken`, `<E>BuildUpTaken`, `<E>BuildUpThreshold`, `<E>BuildUpDecayDelay`, `<E>BuildUpDecayRate`, `<E>StatusDuration`, `<E>StatusImmunity`, `IgniteDamageMult`, `ShockDischargeDamage`, `FrostSlow`; E = Fire, Lightning, Ice) and `Strings` (`<E>StatusReaction`); missing keys fall back to `Game.json` `ElementalDefault.<Key>`. Sources: spell param `BuildUp`, weapon stats `FireBuildUp` / `LightningBuildUp` / `IceBuildUp` and `WeakPointBuildUpMult`, item stat `BuildUp`.

## How the main flows run
- **Cast:** input -> `UGBSpellbookComponent::TryCastSlot` (checks staff in hand, known, cooldown, mana; spends mana) -> `UGBQTEComponent::StartQTE` (slow time, sequence = power, gesture = reach; or instant when off) -> `GBSpell::ResolveCast` (data -> QTE scaling -> modifiers) -> spawn the behavior actor -> it deals damage through `UGBCombatLibrary`.
- **Shoot:** input -> `AGBGun` (fire interval, magazine, spread, recoil, pellets; every number via `GetStat`) -> hitscan -> headshot and distance falloff math in `UGBCombatLibrary` -> `DealDamage`.
- **Era travel:** `AGBPortal::Interact` -> `UGBEraSubsystem::RequestTravel` (fade out, swap era for `UGBEraComponent` actors and `_Past` / `_Future` sub-levels, teleport, restore health/mana/ammo, save checkpoint, fade in).
- **Progress:** encounters set flags in `UGBProgressSubsystem` when cleared; `UGBEraComponent` reads flags, which is how era-gated zones and past-to-future unlocks are built. Death restores the last checkpoint snapshot; flags are never rolled back (enemies do not respawn).
- **Elemental build-up:** a hit carries `FGBDamageInfo::BuildUp` (spell param, weapon stat by element, item stat) and a `BuildUpEventId` (one per shot, cast, blast or tick). `DealDamage` passes it to the target's `UGBElementalStatusComponent` (`ApplyBuildUp`; the ice floor, which deals no damage, calls it directly), which dedupes by event id, applies the enemy's resistance and fills one of three `FGBBuildUpMeter`s. A full bar starts the status: Ignite is the `Ignite` status effect (DOT through `DealDamage`); Shock deals its discharge; Frost slow is a `MultiplyMin` modifier; stun, interrupt and freeze are done by `AGBEnemyCharacter` from the component's `OnStatusStarted` event. The component only ticks (every `ElementalTickInterval`) while a bar is not empty. Looks bind to its events; `gb.ShowElemental 1` is a debug view and `gb.BuildUp` a test command.
- **Upgrades:** `UGBSkillTreeComponent::Unlock` adds the node's modifiers to the player's stats; weapons and spells pick them up on their next read.

## Conventions
- Game text in English. Code comments in English. ASCII only in source files.
- Native multicast delegates (C++ project; no Blueprint graphs needed).
- No custom collision channels: projectiles and queries use the default channels and filter by team in code.
- Pointers to definitions are not kept across frames (data can be reloaded): keep the id, look it up.
- Tests: only pure logic that is easy to break and hard to see by playing; each one must be able to fail; names `Glyphbound.<Area>.<Name>` where a name is never also a prefix of another.
- Build: `powershell -File Tools/Jam/Build-Jam.ps1` (Editor closed). One build at a time per machine.
- Art rule in code: characters, items and effects are camera-facing pixel sprites; **structures are 3D shapes with pixel tiles** (`GBPlaceholder::SetupTexturedShape`, tiles are sprites of `Sprites.json` named `tile_*`). The material behind it (`M_PixelSurface`) is the only binary asset and is generated by `Tools/Jam/Make-Materials.ps1`, never edited by hand.
- A structure that looks different in each era has ONE hidden collision body present in both eras and two non-colliding looks (PastOnly / FutureOnly), so footing and navigation never change on era travel.
- UI that reacts to combat listens to `UGBCombatLibrary::OnDamageDealt()`; nothing in combat code knows about the HUD.
# Pixel-art visual style guide

> **Source.** The 9 sprites this guide is built from (`valki`, `axe`, `spada`, `sscudo`, `sscudo adnto`, `baston1`, `baston1.2`, `baston2`, `baston3`) were drawn **by hand in Pixelorama on the LAPTOP on 2026-11-12**, during the jam (file times 12:45 to 21:32 local, UTC-4). Log: `Devlog/raw/LAPTOP/2026-11-13/transcripts/cursor-2e46aba0-*.jsonl`.
>
> It complements GDD Â§3 "Art rule": that section says **what** is pixel art; this guide says **how** it is drawn. Where they disagree, the GDD wins.

---

## 1. The style in one line

> **Dark fantasy hi-bit pixel art, 16-bit inspired.**

- **Hi-bit:** modern pixel art that keeps the retro language (hard pixels, outline, a small palette per sprite) without a console's limits: large sprites, more colors, fine detail.
- **16-bit inspired:** the SNES / Mega Drive tradition: ramp shading, a dark outline, pinpoint highlights.
- **Dark fantasy:** dark base materials (iron, obsidian) with saturated accents (blood, fire, arcane, ice).

Tone references (reference only, nothing copied): *Castlevania: Symphony of the Night*, *Blasphemous*, *Eitr*, *Children of Morta*.

---

## 2. Visual pillars

1. **Silhouette first.** Every object reads from its black shape alone: crescent axe, straight sword, round shield, staff with an ornate head.
2. **Dark material + bright accent.** Most of a sprite is muted. Saturated color is kept for what is magical or important: gems, orbs, blades, hair.
3. **Clean pixels.** No semi-transparency and no automatic anti-aliasing. Every current sprite already follows this (alpha is 0 or 255).
4. **Few ramps, well chosen.** Each material has a fixed ramp; no new tones invented sprite by sprite.

---

## 3. Format and scale

| Rule | Value |
|---|---|
| Asset canvas (weapons, shields, characters) | 100Ã—100 px |
| Longest side of the sprite | 88â€“96 px |
| Minimum margin to the canvas edge | 2 px |
| Resolution | 1:1, no scaling inside the canvas |
| Transparency | 0% or 100% only |
| Animation frame rate | 6 fps as a base (what the files already use) |

**To decide:** the character (`valki`, 93 px) and the weapons (89â€“99 px) are almost the same height today. That works for inventory icons or equipment cards, not for weapons held in the game. Define two scales:

- **Icon scale:** the current one, the object filling the canvas.
- **World scale:** the weapon in proportion to the character's hand. For example, a sword of about 40â€“50 px for a 93 px character.

`axe` is 99 px tall and touches the canvas edge; shrink or re-center it to keep the margin.

---

## 4. Outline

- **Outer outline:** `#000000`, 1 px, all around. It is already the outline color of `valki`, `axe`, `spada` and the shields.
- **Inner outline** (between parts, such as blade and guard or strap and metal): the darkest tone of the material's ramp, not black.
- **Staffs:** today their darkest tone is `#1D1D25` and they have no black outline. Pick one option and apply it to all four:
  - Add a `#000000` outline outside, to match the rest (recommended).
  - Keep them without black and record it as the exception of the "obsidian" family.
- **Thickness:** always 1 px. Avoid doubled corners (a 2 px outline on diagonals) unless weight is wanted on purpose.

---

## 5. Light and shading

- **Light source:** top left. The highlights on the shield and the sword blade already follow it; apply it to everything.
- **Ramp per material:** 3 to 5 tones (deep shadow, shadow, base, light, specular).
- **Specular highlight:** 1 to 3 near-white pixels, only on polished metal, gems and orbs. Never on wood, cloth or stone.
- **Hue-shifted ramps:** shadows lean cold (blue or violet), lights lean warm (yellow). It brings life to dark fantasy and avoids "dirty" greys.
- **Texture:** the loose-pixel noise on the shield works as wear. Use it only on rough materials (old iron, stone, wood), never on polished metal or skin.
- **Dithering:** optional, and only on large flat surfaces. Avoid it on small or animated sprites.

---

## 7. Design language by family

### Staffs (variant system)
A very good system already exists; this formalizes it:

| Variant | Shaft | Head | Reads as |
|---|---|---|---|
| `baston1` | reddish wood | silver orb | basic / mundane |
| `baston1.2` | obsidian | arcane orb + floating particles | void / shadow |
| `baston2` | obsidian | ice orb | ice |
| `baston3` | obsidian + lava veins | fire orb | fire |

**Rule:** the base silhouette (22Ã—90 px) stays; only the accent ramp changes. The loose particles of `baston1.2` and the veins of `baston3` are a good marker of "magic level". Use them consistently: the basic variant has no effects, the elemental ones have veins or particles.

### Metal weapons
Dark iron, black outline and a single red accent (gem or fuller). The sword and the axe already follow this.

### Shields
A round iron base with textured wear and a raised cross. The ornate version adds arcane gems and a wooden strap. Future variants change the ornaments, not the base.

### Characters
Valki sets the reference: armor in a solid saturated color, hair as the main accent, and secondary elements (wings) in muted ivory so they do not compete with the body.

---

## 8. What we never do

- Colors outside the master palette.
- Automatic anti-aliasing, semi-transparency, blur or smooth gradients.
- Pure white `#FFFFFF` or stray whites. Only `#F0F0F0` exists.
- Saturated accents on large surfaces (an accent is small and pinpoint).
- Black and non-black outlines mixed inside one family.
- Light from different directions on sprites shown together.
- Texture noise on polished metal or skin.

# make_materials.py - Unreal Editor Python script that (re)builds the project's few materials from text.
#
# The .uasset files are not in git (Content/ is ignored except Content/Data), so this script IS the source of the
# materials. Run it through Tools/Jam/Make-Materials.ps1 (UnrealEditor-Cmd -run=pythonscript), Editor closed.
#
# M_PixelSurface (/Game/Glyphbound/Materials/M_PixelSurface): the look of every medieval / magic structure
# (GDD 3: "pixel-art environments are 3D geometry with low-resolution pixel textures"). Used from C++ by
# GBPlaceholder::SetupTexturedShape through a dynamic material instance. Parameters:
#   Texture   (texture object) the tile, a transient texture set at runtime (wrap addressing, nearest filter)
#   TileSize  (scalar, cm)     one tile covers TileSize x TileSize cm in the world, on every face
#   Tint      (vector)         multiplies the texture color
#   Glow      (scalar)         emissive = color * Glow (0 = plain lit surface)
#
# Why the projection is built by hand instead of using the engine function WorldAlignedTexture: the texture sample
# inside that function uses the shared sampler "Wrap, World group settings", which takes its filtering from the
# World texture group (smooth). Pixel art needs the texture's own nearest filter, so our sample uses
# "From texture asset" and the world-space projection is rebuilt here: absolute world position / TileSize, and the
# projection plane is picked by the dominant axis of the vertex normal (hard switch, no blending between planes).

import unreal

MATERIAL_DIR = "/Game/Glyphbound/Materials"
PIXEL_SURFACE = "M_PixelSurface"
PIXEL_DECAL = "M_PixelDecal"
DEFAULT_TEXTURE = "/Engine/EngineMaterials/DefaultDiffuse.DefaultDiffuse"

MEL = unreal.MaterialEditingLibrary


def log(message):
    unreal.log("make_materials: " + message)


def fail(message):
    unreal.log_error("make_materials: ERROR " + message)
    raise RuntimeError(message)


def get_or_create_material(directory, name):
    path = directory + "/" + name
    if unreal.EditorAssetLibrary.does_asset_exist(path):
        material = unreal.EditorAssetLibrary.load_asset(path)
        if not isinstance(material, unreal.Material):
            fail("%s exists but is not a Material" % path)
        # Rebuild the graph from scratch so the asset always matches this script.
        MEL.delete_all_material_expressions(material)
        log("rebuilding %s" % path)
        return material
    if not unreal.EditorAssetLibrary.does_directory_exist(directory):
        unreal.EditorAssetLibrary.make_directory(directory)
    tools = unreal.AssetToolsHelpers.get_asset_tools()
    material = tools.create_asset(name, directory, unreal.Material, unreal.MaterialFactoryNew())
    if material is None:
        fail("could not create %s" % path)
    log("created %s" % path)
    return material


class Graph(object):
    def __init__(self, material):
        self.material = material
        self.x = -1600

    def node(self, expression_class, x, y, **properties):
        expression = MEL.create_material_expression(self.material, expression_class, x, y)
        if expression is None:
            fail("could not create %s" % expression_class.__name__)
        for key, value in properties.items():
            expression.set_editor_property(key, value)
        return expression

    def connect(self, source, source_output, target, target_inputs):
        """target_inputs: one input name or a list of accepted names (script name first, full name second)."""
        if isinstance(target_inputs, str):
            target_inputs = [target_inputs]
        for target_input in target_inputs:
            if MEL.connect_material_expressions(source, source_output, target, target_input):
                return
        fail("cannot connect %s.%r -> %s.%r (outputs %s, inputs %s)" % (
            source.get_class().get_name(), source_output, target.get_class().get_name(), target_inputs,
            list(MEL.get_material_expression_output_names(source)),
            list(MEL.get_material_expression_input_names(target))))

    def to_property(self, source, source_output, material_property):
        if not MEL.connect_material_property(source, source_output, material_property):
            fail("cannot connect %s.%r -> %s (outputs %s)" % (
                source.get_class().get_name(), source_output, material_property,
                list(MEL.get_material_expression_output_names(source))))


def mask(graph, source, x, y, r=False, g=False, b=False, a=False):
    expression = graph.node(unreal.MaterialExpressionComponentMask, x, y, r=r, g=g, b=b, a=a)
    graph.connect(source, "", expression, ["", "Input"])
    return expression


def build_pixel_surface():
    material = get_or_create_material(MATERIAL_DIR, PIXEL_SURFACE)
    material.set_editor_property("blend_mode", unreal.BlendMode.BLEND_OPAQUE)
    material.set_editor_property("shading_model", unreal.MaterialShadingModel.MSM_DEFAULT_LIT)
    material.set_editor_property("two_sided", False)

    default_texture = unreal.load_asset(DEFAULT_TEXTURE)
    if default_texture is None:
        fail("cannot load the default texture %s" % DEFAULT_TEXTURE)

    g = Graph(material)

    # ---- Parameters ----
    texture = g.node(unreal.MaterialExpressionTextureObjectParameter, -1400, -500,
                     parameter_name="Texture", texture=default_texture,
                     sampler_type=unreal.MaterialSamplerType.SAMPLERTYPE_COLOR)
    tile_size = g.node(unreal.MaterialExpressionScalarParameter, -2000, 0,
                       parameter_name="TileSize", default_value=100.0)
    tint = g.node(unreal.MaterialExpressionVectorParameter, -600, -250,
                  parameter_name="Tint", default_value=unreal.LinearColor(1.0, 1.0, 1.0, 1.0))
    glow = g.node(unreal.MaterialExpressionScalarParameter, -400, 150,
                  parameter_name="Glow", default_value=0.0)

    # ---- World-space coordinates in tiles ----
    world_position = g.node(unreal.MaterialExpressionWorldPosition, -2000, -150)
    in_tiles = g.node(unreal.MaterialExpressionDivide, -1800, -100)
    g.connect(world_position, "", in_tiles, "A")
    g.connect(tile_size, "", in_tiles, "B")

    wx = mask(g, in_tiles, -1650, -250, r=True)
    wy = mask(g, in_tiles, -1650, -150, g=True)
    wz = mask(g, in_tiles, -1650, -50, b=True)
    # Texture rows go top to bottom: V = -Z keeps the sprite upright on walls.
    wz_down = g.node(unreal.MaterialExpressionMultiply, -1500, -50, const_b=-1.0)
    g.connect(wz, "", wz_down, "A")

    uv_x = g.node(unreal.MaterialExpressionAppendVector, -1300, -250)  # faces looking along X
    g.connect(wy, "", uv_x, "A")
    g.connect(wz_down, "", uv_x, "B")
    uv_y = g.node(unreal.MaterialExpressionAppendVector, -1300, -150)  # faces looking along Y
    g.connect(wx, "", uv_y, "A")
    g.connect(wz_down, "", uv_y, "B")
    uv_z = g.node(unreal.MaterialExpressionAppendVector, -1300, -50)   # floors and ceilings
    g.connect(wx, "", uv_z, "A")
    g.connect(wy, "", uv_z, "B")

    # ---- Pick the plane by the dominant axis of the normal ----
    normal = g.node(unreal.MaterialExpressionVertexNormalWS, -2000, 250)
    normal_abs = g.node(unreal.MaterialExpressionAbs, -1800, 250)
    g.connect(normal, "", normal_abs, ["", "Input"])
    nx = mask(g, normal_abs, -1650, 200, r=True)
    ny = mask(g, normal_abs, -1650, 300, g=True)
    nz = mask(g, normal_abs, -1650, 400, b=True)

    uv_side = g.node(unreal.MaterialExpressionIf, -1100, -150)
    g.connect(nx, "", uv_side, "A")
    g.connect(ny, "", uv_side, "B")
    g.connect(uv_x, "", uv_side, ["A > B", "AGreaterThanB"])
    g.connect(uv_y, "", uv_side, ["A == B", "AEqualsB"])
    g.connect(uv_y, "", uv_side, ["A < B", "ALessThanB"])

    side_max = g.node(unreal.MaterialExpressionMax, -1300, 300)
    g.connect(nx, "", side_max, "A")
    g.connect(ny, "", side_max, "B")

    uv = g.node(unreal.MaterialExpressionIf, -900, -100)
    g.connect(nz, "", uv, "A")
    g.connect(side_max, "", uv, "B")
    g.connect(uv_z, "", uv, ["A > B", "AGreaterThanB"])
    g.connect(uv_side, "", uv, ["A == B", "AEqualsB"])
    g.connect(uv_side, "", uv, ["A < B", "ALessThanB"])

    # ---- Sample with the texture's own filter and addressing (nearest + wrap for tiles) ----
    sample = g.node(unreal.MaterialExpressionTextureSample, -700, -300,
                    sampler_source=unreal.SamplerSourceMode.SSM_FROM_TEXTURE_ASSET,
                    sampler_type=unreal.MaterialSamplerType.SAMPLERTYPE_COLOR)
    g.connect(texture, "", sample, ["Tex", "TextureObject"])
    g.connect(uv, "", sample, ["UVs", "Coordinates"])

    tint_rgb = mask(g, tint, -450, -250, r=True, g=True, b=True)
    color = g.node(unreal.MaterialExpressionMultiply, -300, -300)
    g.connect(sample, "RGB", color, "A")
    g.connect(tint_rgb, "", color, "B")

    emissive = g.node(unreal.MaterialExpressionMultiply, -150, 0)
    g.connect(color, "", emissive, "A")
    g.connect(glow, "", emissive, "B")

    roughness = g.node(unreal.MaterialExpressionConstant, -150, 150, r=0.9)

    g.to_property(color, "", unreal.MaterialProperty.MP_BASE_COLOR)
    g.to_property(emissive, "", unreal.MaterialProperty.MP_EMISSIVE_COLOR)
    g.to_property(roughness, "", unreal.MaterialProperty.MP_ROUGHNESS)

    check_and_save(material, PIXEL_SURFACE)

def check_and_save(material, name):
    errors = MEL.recompile_material(material)
    if errors:
        for error in errors:
            unreal.log_error("make_materials: ERROR compile: %s" % error)
        fail("%s has compile errors" % name)
    bad_nodes = MEL.get_material_error_expressions(material)
    if bad_nodes:
        fail("%s: %d expressions report errors: %s" % (
            name, len(bad_nodes), [n.get_class().get_name() for n in bad_nodes]))

    path = MATERIAL_DIR + "/" + name
    if not unreal.EditorAssetLibrary.save_asset(path, only_if_is_dirty=False):
        fail("could not save %s" % path)
    log("saved %s (params: %s %s %s)" % (
        path,
        list(MEL.get_texture_parameter_names(material)) if hasattr(MEL, "get_texture_parameter_names") else "",
        list(MEL.get_scalar_parameter_names(material)) if hasattr(MEL, "get_scalar_parameter_names") else "",
        list(MEL.get_vector_parameter_names(material)) if hasattr(MEL, "get_vector_parameter_names") else ""))


def build_pixel_decal():
    # Ground spell figures (GDD 3 and 18): one flat quad on the floor with the spell's sprite stretched
    # once over it. Masked (cutout) so transparent pixels show the floor; mesh UVs (TexCoord 0), not
    # world position; the texture's own nearest sampler (same reason as M_PixelSurface: the shared
    # world-group sampler would smooth the pixels).
    material = get_or_create_material(MATERIAL_DIR, PIXEL_DECAL)
    material.set_editor_property("blend_mode", unreal.BlendMode.BLEND_MASKED)
    material.set_editor_property("shading_model", unreal.MaterialShadingModel.MSM_DEFAULT_LIT)
    material.set_editor_property("two_sided", True)
    material.set_editor_property("opacity_mask_clip_value", 0.5)

    default_texture = unreal.load_asset(DEFAULT_TEXTURE)
    if default_texture is None:
        fail("cannot load the default texture %s" % DEFAULT_TEXTURE)

    g = Graph(material)

    # ---- Parameters (same names as M_PixelSurface where they mean the same) ----
    texture = g.node(unreal.MaterialExpressionTextureObjectParameter, -1400, -500,
                     parameter_name="Texture", texture=default_texture,
                     sampler_type=unreal.MaterialSamplerType.SAMPLERTYPE_COLOR)
    tint = g.node(unreal.MaterialExpressionVectorParameter, -600, -250,
                  parameter_name="Tint", default_value=unreal.LinearColor(1.0, 1.0, 1.0, 1.0))
    glow = g.node(unreal.MaterialExpressionScalarParameter, -400, 150,
                  parameter_name="Glow", default_value=0.0)

    # ---- Mesh UVs: the whole texture stretched once over the quad ----
    texcoord = g.node(unreal.MaterialExpressionTextureCoordinate, -1300, -100,
                      coordinate_index=0)

    # ---- Sample with the texture's own filter (nearest, no smoothing) ----
    sample = g.node(unreal.MaterialExpressionTextureSample, -700, -300,
                    sampler_source=unreal.SamplerSourceMode.SSM_FROM_TEXTURE_ASSET,
                    sampler_type=unreal.MaterialSamplerType.SAMPLERTYPE_COLOR)
    g.connect(texture, "", sample, ["Tex", "TextureObject"])
    g.connect(texcoord, "", sample, ["UVs", "Coordinates"])

    tint_rgb = mask(g, tint, -450, -250, r=True, g=True, b=True)
    color = g.node(unreal.MaterialExpressionMultiply, -300, -300)
    g.connect(sample, "RGB", color, "A")
    g.connect(tint_rgb, "", color, "B")

    emissive = g.node(unreal.MaterialExpressionMultiply, -150, 0)
    g.connect(color, "", emissive, "A")
    g.connect(glow, "", emissive, "B")

    roughness = g.node(unreal.MaterialExpressionConstant, -150, 150, r=0.9)

    g.to_property(color, "", unreal.MaterialProperty.MP_BASE_COLOR)
    g.to_property(emissive, "", unreal.MaterialProperty.MP_EMISSIVE_COLOR)
    g.to_property(roughness, "", unreal.MaterialProperty.MP_ROUGHNESS)
    g.to_property(sample, "A", unreal.MaterialProperty.MP_OPACITY_MASK)

    check_and_save(material, PIXEL_DECAL)

# Pixel-art visual style guide

> **Source.** The 9 sprites this guide is built from (`valki`, `axe`, `spada`, `sscudo`, `sscudo adnto`, `baston1`, `baston1.2`, `baston2`, `baston3`) were drawn **by hand in Pixelorama on the LAPTOP on 2026-11-12**, during the jam (file times 12:45 to 21:32 local, UTC-4). The guide was drafted the same evening by Cursor on the LAPTOP, which read the `.pxo` files, measured them (canvas, colors, alpha) and wrote it in Spanish at the artist's request. This is the English translation, made by the architect on CENTRAL; the Spanish original and the `.pxo` sources are in `Glyphbound/SourceArt/PixelArt/` (see its README). Log: `Devlog/raw/LAPTOP/2026-11-13/transcripts/cursor-2e46aba0-*.jsonl`.
>
> It complements GDD §3 "Art rule": that section says **what** is pixel art; this guide says **how** it is drawn. Where they disagree, the GDD wins.

---

## 1. The style in one line

> **Dark fantasy hi-bit pixel art, 16-bit inspired.**

- **Hi-bit:** modern pixel art that keeps the retro language (hard pixels, outline, a small palette per sprite) without a console's limits: large sprites, more colors, fine detail.
- **16-bit inspired:** the SNES / Mega Drive tradition: ramp shading, a dark outline, pinpoint highlights.
- **Dark fantasy:** dark base materials (iron, obsidian) with saturated accents (blood, fire, arcane, ice).

Tone references (reference only, nothing copied): *Castlevania: Symphony of the Night*, *Blasphemous*, *Eitr*, *Children of Morta*.

---

## 2. Visual pillars

1. **Silhouette first.** Every object reads from its black shape alone: crescent axe, straight sword, round shield, staff with an ornate head.
2. **Dark material + bright accent.** Most of a sprite is muted. Saturated color is kept for what is magical or important: gems, orbs, blades, hair.
3. **Clean pixels.** No semi-transparency and no automatic anti-aliasing. Every current sprite already follows this (alpha is 0 or 255).
4. **Few ramps, well chosen.** Each material has a fixed ramp; no new tones invented sprite by sprite.

---

## 3. Format and scale

| Rule | Value |
|---|---|
| Asset canvas (weapons, shields, characters) | 100×100 px |
| Longest side of the sprite | 88–96 px |
| Minimum margin to the canvas edge | 2 px |
| Resolution | 1:1, no scaling inside the canvas |
| Transparency | 0% or 100% only |
| Animation frame rate | 6 fps as a base (what the files already use) |

**To decide:** the character (`valki`, 93 px) and the weapons (89–99 px) are almost the same height today. That works for inventory icons or equipment cards, not for weapons held in the game. Define two scales:

- **Icon scale:** the current one, the object filling the canvas.
- **World scale:** the weapon in proportion to the character's hand. For example, a sword of about 40–50 px for a 93 px character.

`axe` is 99 px tall and touches the canvas edge; shrink or re-center it to keep the margin.

---

## 4. Outline

- **Outer outline:** `#000000`, 1 px, all around. It is already the outline color of `valki`, `axe`, `spada` and the shields.
- **Inner outline** (between parts, such as blade and guard or strap and metal): the darkest tone of the material's ramp, not black.
- **Staffs:** today their darkest tone is `#1D1D25` and they have no black outline. Pick one option and apply it to all four:
  - Add a `#000000` outline outside, to match the rest (recommended).
  - Keep them without black and record it as the exception of the "obsidian" family.
- **Thickness:** always 1 px. Avoid doubled corners (a 2 px outline on diagonals) unless weight is wanted on purpose.

---

## 5. Light and shading

- **Light source:** top left. The highlights on the shield and the sword blade already follow it; apply it to everything.
- **Ramp per material:** 3 to 5 tones (deep shadow, shadow, base, light, specular).
- **Specular highlight:** 1 to 3 near-white pixels, only on polished metal, gems and orbs. Never on wood, cloth or stone.
- **Hue-shifted ramps:** shadows lean cold (blue or violet), lights lean warm (yellow). It brings life to dark fantasy and avoids "dirty" greys.
- **Texture:** the loose-pixel noise on the shield works as wear. Use it only on rough materials (old iron, stone, wood), never on polished metal or skin.
- **Dithering:** optional, and only on large flat surfaces. Avoid it on small or animated sprites.

---

## 6. Master palette

Today the 9 sprites use **81 unique colors**, and the loaded palette (*DawnBringer 32 copy*) is barely used. There are also duplicates the eye cannot tell apart (`#000000`/`#010101`, `#434848`/`#434846`, and six different whites). The proposal consolidates them into fixed ramps, starting from the colors already in use.

### Neutrals and outline
| Use | Colors |
|---|---|
| Outline | `#000000` |
| Specular white (the only one) | `#F0F0F0` |

### Iron / steel (shield, axe, sword)
`#262827` → `#373837` → `#434848` → `#555957` → `#758685` → `#9DAAA9` → `#B8C3BD` → `#E5DCDC`

- Old dark iron (shield, axe): the first 5 tones, with `#B8C3BD` as the highlight.
- Polished steel (sword): from `#758685` to `#E5DCDC`.
- The axe blade uses warm greys (`#2F2A2A`, `#544F49`, `#B7B3AF`). Move it to this ramp, or create a "warm iron" ramp and document it.

### Obsidian (shaft of the magic staffs)
`#1D1D25` → `#252734` → `#32343C` → `#655478` (light)

`#F9C990` → `#FBD6AA` → `#EFD9BF`

A skin shadow tone is missing. Add a warm, slightly pink one, around `#C88A6A`.

|---|---|---|
| Blood / red | `#4B0A0A` → `#810505` → `#B70000` → `#FF0000` | sword fuller, axe gem, Valki's hair |

### Color budget per sprite
- Weapons and items: up to 16 colors.
- Characters: up to 24 colors.
- At most 1 or 2 accent ramps per sprite.

---

## 7. Design language by family

### Staffs (variant system)
A very good system already exists; this formalizes it:

| Variant | Shaft | Head | Reads as |
|---|---|---|---|
| `baston1` | reddish wood | silver orb | basic / mundane |
| `baston1.2` | obsidian | arcane orb + floating particles | void / shadow |
| `baston2` | obsidian | ice orb | ice |
| `baston3` | obsidian + lava veins | fire orb | fire |

**Rule:** the base silhouette (22×90 px) stays; only the accent ramp changes. The loose particles of `baston1.2` and the veins of `baston3` are a good marker of "magic level". Use them consistently: the basic variant has no effects, the elemental ones have veins or particles.

### Metal weapons
Dark iron, black outline and a single red accent (gem or fuller). The sword and the axe already follow this.

### Shields
A round iron base with textured wear and a raised cross. The ornate version adds arcane gems and a wooden strap. Future variants change the ornaments, not the base.

### Characters
Valki sets the reference: armor in a solid saturated color, hair as the main accent, and secondary elements (wings) in muted ivory so they do not compete with the body.

---

## 8. What we never do

- Colors outside the master palette.
- Automatic anti-aliasing, semi-transparency, blur or smooth gradients.
- Pure white `#FFFFFF` or stray whites. Only `#F0F0F0` exists.
- Saturated accents on large surfaces (an accent is small and pinpoint).
- Black and non-black outlines mixed inside one family.
- Light from different directions on sprites shown together.
- Texture noise on polished metal or skin.

---

## 9. Current inconsistencies and actions

| Problem | Files | Action |
|---|---|---|
| 81 colors, most outside DB32 | all | Remap to the master palette |
| Six near-identical whites | `valki`, `spada`, `baston*` | Unify on `#F0F0F0` |
| `#010101` instead of `#000000` | `axe` | Replace with `#000000` |
| `#434846` duplicating `#434848` | shields | Replace with `#434848` |
| Staffs without a black outline | `baston*` | Decide the rule (section 4) |
| Axe touching the edge (99 px) | `axe` | Shrink or re-center with a 2 px margin |
| Two different wood tones | `axe`, `baston1` | Unify the ramp |
| Warm greys on the axe | `axe` | Move to the iron ramp or document them |
| No saved palette | `baston1.2`, `baston2`, `baston3` | Assign the project palette |

---

## 10. Checklist before a sprite is done

- [ ] 100×100 canvas, longest side 88–96 px, 2 px margin.
- [ ] Silhouette readable in pure black.
- [ ] 1 px outer outline following its family's rule.
- [ ] Light from the top left.
- [ ] Every color is in the master palette.
- [ ] Within the color budget (16 for items, 24 for characters).
- [ ] At most 1 or 2 saturated accents.
- [ ] No semi-transparency.
- [ ] Next to the other sprites of its family, it looks like the same game.

bool FModuleDescriptor::IsLoadedInCurrentConfiguration() const
{
	// Check that the module is built for this configuration
	if(!IsCompiledInCurrentConfiguration())
	{
		return false;
	}

	
	// Always respect the allow/deny lists for program targets
	EBuildTargetType TargetType = FApp::GetBuildTargetType();
	if(TargetType == EBuildTargetType::Program)
	{
		const FString TargetName = UE_APP_NAME;
			
		// Check the program name is allowed. Note that this behavior is slightly different to other allow/deny list checks; we will allow a module of any type if it's explicitly allowed for this program.
		if(ProgramAllowList.Num() > 0)
		{
			return ProgramAllowList.Contains(TargetName);
		}
				
		// Check the program name is not denied
		if(ProgramDenyList.Contains(TargetName))
		{
			return false;
		}
	}
	else
	{
		const FString TargetName = UE_APP_NAME;
		
		if(GameTargetAllowList.Num() > 0 && !GameTargetAllowList.Contains(TargetName))
		{
			return false;
		}
				
		if(GameTargetDenyList.Contains(TargetName))
		{
			return false;
		}
	}

	// Check that the runtime environment allows it to be loaded
	switch (Type)
	{
	case EHostType::RuntimeAndProgram:
		#if (WITH_ENGINE || WITH_PLUGIN_SUPPORT)
			return true;
		#else
			break;
		#endif

	case EHostType::Runtime:
		#if (WITH_ENGINE || WITH_PLUGIN_SUPPORT) && !IS_PROGRAM
			return true;
		#else
			break;
		#endif
	
	case EHostType::RuntimeNoCommandlet:
		#if (WITH_ENGINE || WITH_PLUGIN_SUPPORT)  && !IS_PROGRAM
			if(!IsRunningCommandlet()) return true;
		#else
			break;
		#endif

	case EHostType::CookedOnly:
		return FPlatformProperties::RequiresCookedData();

	case EHostType::UncookedOnly:
		return !FPlatformProperties::RequiresCookedData();

	case EHostType::Developer:
		#if WITH_EDITOR || IS_PROGRAM
			return true;
		#else
			return false;
		#endif

	case EHostType::DeveloperTool:
		#if WITH_UNREAL_DEVELOPER_TOOLS
			return true;

	}
	
	TotalDispatchesThisFrame = 0;

	// Add pass to begin the gpu profiler frame
#if WITH_NIAGARA_GPU_PROFILER
	GPUProfilerPtr->BeginFrame(GraphBuilder.RHICmdList);

#if STATS

	if (bAllowGPUParticleUpdate && ((IsFirstViewFamily() && GPUInstanceCounterManager.HasEntriesPendingFree()) || HasAnyWork()))
	{
