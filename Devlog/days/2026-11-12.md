## Design decisions
All taken by the architect; the owner asked not to be consulted on engineering.

- **C++ only, built from the blank template.** The first-person template was not used: the jam asks for gameplay beyond Epic's templates, and AI agents handle C++ text far better than Blueprint graphs.
- **No Gameplay Ability System.** Considered (the GDD lists it as a candidate) and rejected: heavy boilerplate and asset setup for a 4-day jam. Replaced by three small pieces we fully control: one stat system (base value from data + stacked modifiers), one damage function, one status-effect component. Skill-tree nodes, armor, slows, potions, air passives and the weapon enchant are all "a named group of modifiers".
- **All gameplay numbers in JSON under `Content/Data`, shipped as loose files.** Reasons: git only carries text in this team (binary assets travel by a shared folder), AI agents edit text reliably, and the owner can retune a packaged build with a text editor and no Editor. `gb.ReloadData` reloads while playing. The GDD suggested data tables; JSON gives the same thing without binary assets.
- **Spells = data + a behavior class.** Each parameter has `Base / Min / Max / ScaledBy` (none, QTE power, QTE reach). Eight behaviors cover the nine active spells and the enchant; a new spell that fits a behavior is one JSON entry.
- **No binary assets needed to run.** The test arena, input actions and placeholders are built in C++; placeholder pixel art is ASCII rows in `Sprites.json` turned into textures at runtime. The default map is the engine's empty map, so the Editor boots on an empty level and the whole game is reviewable as text in git.
- **HUD drawn with the canvas, not widgets.** Two skins (90s RPG, cyberpunk) are two style structs. No widget assets to author by hand.
- **Contracts first, then parallel implementers.** The architect wrote every public header with the specification in comments, checked that they pass Unreal's header tool, and only then started ten implementers, each owning one folder and forbidden to touch the others. Reason: parallel agents drift apart unless the interfaces are fixed first.
- **Plugins:** the `AllToolsets` aggregator was replaced by the 18 Editor toolsets we use, and 103 default plugins were turned off by a script that checks every plugin dependency first (`Tools/Jam/trim_plugins.js`).

## Problems and solutions
- **Trimming plugins did not speed up a warm Editor boot.** We expected a gain; measured, there is none worth the name (see Numbers). Mounted plugins went from 315 to 160, but warm boot stayed around 10-11 s. The cost of a warm boot is not in the plugin count. We keep the trimmed list anyway (fewer modules to load and cook, smaller package), and we did not spend more time on it. Lesson from the previous project confirmed: measure the whole thing before believing an optimization.
