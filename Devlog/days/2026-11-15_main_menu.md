# 2026-11-15 — The title screen, in two looks (side session)

**Request (orchestrator, then the owner):** a main menu that opens when the game starts, with a staff selection before playing. The owner added (translated from Spanish): "the main menu should look like the rest of the HUD. The default will be the pixel art, but also make the menu with cyberpunk art, following the guidelines of the rest of the HUD and the game's interface. In the menu, one button switches from one interface to the other. Everything else stays the same: New Game, Continue, Options, that kind of thing." He offered a Fab asset (Easy Menu) as a guide for the options screen; it was not needed (see below).

**Who did it:** the architect implemented directly (Claude Opus 5.5 side session). Exception to the Muse rule because of the deadline and because the menu reuses many private HUD drawing pieces that a brief would have had to explain.

## Decisions (architect)
- **No UMG, no new map.** The title screen is one more screen of the canvas HUD (`EGBMenu::MainMenu`, `UI/GBHUD_MainMenu.cpp`), drawn over the start map (`PastCastle`) with the game paused. It reuses the menus' pieces: the RPG stone window, gold plaque, carved rows and gold arrow; the cyberpunk near-black screen with grid, scanlines, cut-corner rows and a glitching condensed title. The startup map and packaging do not change.
- **Easy Menu was not used:** it is a UMG asset with its own look; drawing the options with the HUD's own pieces keeps one style and adds no third-party asset to declare.
- **Two looks, one layout.** The look is the menu's own (not the era's): pixel art by default; the "Look" button at the bottom right, Tab, R or the gamepad's top face button switch it, and the menus' existing skin transition (pixel dissolve / scan sweep) covers the switch. The choice is remembered in `GameUserSettings.ini`.
- **Entries:** New Game, Continue, Options, Quit. New Game opens "Choose your staff": the four staffs of `Weapons.json` as cards (sprite, element, damage, shots per second, one line). The pick replaces Player.json's starting staff: in place at boot, and on every fresh start after (the player's `BeginPlay` reads it from a progress flag, so a map restart without a checkpoint keeps it).
- **Continue (provisional):** saving is checkpoints in memory only (GDD 0.1), so at boot there is nothing to continue and the entry is greyed out. The pause menu gained a "Main menu" entry; from there Continue goes back to the run, and New Game starts a fresh run on the start map (`ResetProgress` + `OpenLevel`).
- **Options:** menu look, display (fullscreen / windowed), V-Sync, graphics quality (Low to Epic), master volume, mouse sensitivity (new cvar `gb.MouseSensitivityScale`). Display and graphics only apply in the packaged game (in PIE they would resize or rescale the Editor itself); everything is saved.
- **Once per run:** the menu opens on the first tick that has a HUD, once per game instance; level travel (the seal) and map restarts do not show it again. `-NoMenu` on the command line skips it for test launches.

## Checks
Compile + self-review only (final-stretch rule, no smoke or tests); a human tests it in PIE.
